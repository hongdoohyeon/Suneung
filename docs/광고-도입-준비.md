# 광고 도입 준비

2026-09-13 현재 광고 계정·사이트 승인·게시자 ID가 없다. 광고를 실제 송출하거나 수익이 발생하는 상태가 아니다.

## 배치

우선 Google AdSense 수동 광고 단위로 시작한다. 검색 결과 하단과 시험 자료 영역 아래에 각각 한 곳만 둔다. 문제 다운로드 버튼·PDF 페이지 사이·화면을 덮는 전면 광고는 사용하지 않는다. 홈과 대학 선택 목록은 자료 탐색에 집중한다. 승인 전 빈 광고 자리는 숨긴다.

## 계정에서 필요한 작업

1. [AdSense 가입](https://adsense.google.com/start/) 후 `kicegg.com`을 사이트로 등록한다. 계정 약관 동의와 지급 관련 정보는 운영자가 직접 확인한다.
2. 게시자 ID(`ca-pub-...`)와 사이트 연결 방법을 확인한다. ID는 공개용이며 비밀번호나 지급 정보는 코드에 넣지 않는다.
3. [사이트 연결·심사](https://support.google.com/adsense/answer/7584263?hl=ko)를 완료한다. Google 안내상 승인 전에는 광고가 게재되지 않는다.
4. [반응형 디스플레이 광고 단위](https://support.google.com/adsense/answer/9274025?hl=ko)를 검색 하단·시험 하단용으로 발급한다. 자동 광고는 켜지 않는다.

## 승인·ID 확인 후 코드에서 할 작업

- `lib/ads.js`의 게시자 ID와 `archiveBottom`, `examBottom` 슬롯 ID를 입력한다.
- 계정이 제공하는 정확한 `ads.txt` 레코드를 적용한다. 임의 게시자 ID나 예시값을 게시하지 않는다.
- 현재 HTML meta CSP와 Cloudflare 응답 CSP가 광고 스크립트/프레임을 허용하지 않는다. 실제 사용할 광고 제공자의 공식 지침을 확인해 두 정책을 함께 수정·배포해야 한다. 지금은 광고 계정이 없으므로 CSP를 미리 넓히지 않았다.
- 실제 켜는 서비스와 일치하도록 개인정보처리방침·동의 설정을 점검한다.
- 모바일에서 광고가 PDF·다운로드 링크를 가리지 않는지, 중복으로 요청되지 않는지, 빈 광고가 큰 여백을 남기지 않는지 확인한다.

현재 연동 코드는 광고 ID 형식 검사, 중복 렌더 방지, 오류 로그를 갖추도록 수정했다. 실제 광고 서버와의 연결 검증은 승인·ID가 있어야 할 수 있다.

## 비용·수익 확인

현재 운영 구조는 GitHub Pages와 Cloudflare Worker, GitHub Releases다. 이 구조만으로 비용 증가나 광고 수익을 추정하지 않는다. Cloudflare 청구 화면의 Worker 요청·CPU 사용량·플랜 요금, 사이트 페이지뷰, 광고 승인 후의 실제 노출·수익을 같은 월 단위로 비교한다. 이번 작업에서는 계정 청구 내역과 실제 수익을 조회하지 않았다.

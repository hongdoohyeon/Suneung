# 문항 DB 정규화 작업 점검 보고서 (GPT 전달용)

작성일 2026-10-01 · 작성자 Claude(독립 점검) · 대상 작업: 개별 문항 정규화(`data/question-bank/`, `work/question-bank-pilot/`, `scripts/` 의 question/normalize/apply 계열)

이 문서는 진행 중인 문항 정규화 작업을 **읽기 전용**으로 살펴본 결과다. 코드와 데이터는 수정하지 않았다. 수치는 2026-10-01 00:30 기준 로컬 저장소에서 직접 센 값이다.

## 1. 한눈에

- 설계 문서(`docs/question-content-fidelity.md`, `docs/question-visual-normalization-feedback-20260924.md`)의 방향은 옳다. 원본 PDF 해시·좌표를 증거로 보존하고, 모르는 값은 `NULL`로 두고, 표·그래프·밑줄을 별도 구조로 다루는 원칙을 유지할 것.
- 그러나 **작업 방식이 규모를 감당하지 못한다.** 현재 6%를 문항 단위로 다뤘을 뿐인데 검증 완료 문항은 0개이고, 문항·시험 단위 스크립트가 계속 늘고 있다.
- 권고 요지: (1) 이 DB의 소비처를 먼저 확정, (2) 문항 유형별로 완료 기준을 나눔, (3) 수정은 스크립트가 아니라 데이터로, (4) 검증 자동화와 표본 검수, (5) 작업물을 git 에 올리고 중간 DB 정리.

## 3. 잘 된 점 (유지)

1. 원본 증거 우선: PDF SHA-256, 페이지, 좌표, 무손실 크롭.
2. 알 수 없는 값을 추정하지 않음(`NULL` + 이슈 코드).
3. 문항(`items`)과 시험지 출현(`item_occurrences`)의 분리, 정답 이력(`answer_revisions`) 분리.
4. 시각 요소를 이미지 한 덩어리로 저장하지 않는 원칙(표·그래프·말풍선·선택지 그림을 요소별 대응).
5. 정규화문과 검증 상태를 분리한 4단계 상태(`raw_text_extracted`, `geometry_verified`, `structure_reviewed`, `normalized_text_verified`).
6. 정답이 1~5라는 이유로 객관식으로 추정하지 않고 `response-type-overrides.json` 에 원본 확인을 기록하는 방식.

## 4. 문제점과 권고

### 4.1 소비처(제품 목표)가 문서에 없다

문항 DB 를 어디에 쓰는지에 따라 필요한 완성도가 완전히 다르다. 후보:

- 내부 검색·유사 문항·분석용 (완성도 낮아도 됨)
- 문항별 정답률·오답률 등 통계와 결합한 공개 페이지 (본문 재게시 불필요)
- 문항 본문을 사이트에 공개 (저작권·애드센스 정책 리스크 큼)

**권고:** 목표를 한 줄로 정하고 `data/question-bank/README.md` 맨 위에 적을 것. 특히 **문항 본문을 페이지로 공개하는 방향은 지금(애드센스 승인 전) 피할 것.** 문제 본문 재게시는 저작권 위험이고, 문항 단위 페이지 수만 개는 얇은 대량 페이지로 분류될 수 있다. 공개한다면 메타데이터(과목·단원·정답률)와 원본 링크 중심으로.

참고 자산: `data/raw/item-analytics/`(107MB, EBSi `previous-year-top15` 등)가 있는데 `item_statistics` 테이블이 비어 있다. 문항별 정답률·오답률을 이 DB 에 연결하는 것이 다른 사이트에 없는 가치가 될 가능성이 크다. 연결 가능성과 재배포 가능 범위를 먼저 확인할 것.

### 4.2 "모든 문항 완전 정규화 100%" 기준은 끝나지 않는다

`question-visual-normalization-feedback-20260924.md` 의 결론대로 물리학Ⅰ 20문항조차 완전 정규화·독립 재검수 통과가 0/20이다. 시각 문항 하나에 말풍선·화살표·축·범례까지 전사하는 수준을 16,445문항(향후 수십만)에 적용할 수 없다.

**권고: 유형별 승격 기준을 나눌 것.**

| 유형 | 표현 | 승격 조건 |
|---|---|---|
| 텍스트 위주(국어 독서·문학, 영어, 사탐 다수) | 정규화문 + 블록 구조 | 자동 검사 통과 + 표본 검수로 오류율 확인 |
| 표·그래프·지도·도해 문항 | **원본 크롭을 정답 표현으로**, 구조화는 메타데이터(과목·문항 유형·정답) 위주 | 크롭·좌표 연결 검증 |
| 그림 속 문장·수식·말풍선이 의미를 결정하는 문항 | 별도 트랙, 선별 문항에만 전사 | 독립 검수 |

정규화문이 있는 문항(8,606건)도 "검증된 것"이 아니라는 점을 문서의 수치에서 분명히 구분할 것.

### 4.3 문항·시험별 패치 스크립트 방식은 확장되지 않는다

`scripts/apply-kice-12752-q05-source-review.py` 처럼 시험 id·문항 번호가 파일명에 박힌 스크립트가 43개(전체 `apply-*` 74개)다. 시험 하나에 문항 20개면 스크립트 20개다. 문항이 늘면 관리가 불가능하고 재현·검수 이력이 코드에 흩어진다.

**권고:**

- 수정 내용은 모두 데이터(JSON/CSV)로 표현한다. 이미 `data/question-bank/manual-corrections.json`, `response-type-overrides.json` 이 있다. 같은 방식으로 문항별 교정(`{item_id, field, value, evidence: {pdf_sha, page, bbox}, reviewer, date}`)을 한 곳에 쌓는다.
- 이를 적용하는 스크립트는 **하나**만 둔다(입력: 교정 JSON, 출력: DB). 기존 스크립트는 교정 데이터로 옮긴 뒤 `scripts/_archive/` 로 이동.
- 모든 교정에 근거(원본 좌표·페이지)와 검수자·날짜를 남긴다.

### 4.4 검증을 자동화하고 사람 검수는 큐의 나머지에만

리뷰 큐 78,536건은 사람이 볼 수 없다. 다음을 자동화해 큐를 줄일 것.

1. **텍스트 커버리지 diff**: 원본 PDF 에서 뽑은 문자 집합과 정규화문·블록에서 재구성한 문자 집합의 차이를 문항별로 계산. 누락·중복 문자를 수치화한다.
2. **구조 정합성**: 문항 번호 연속성, 선지 개수(객관식은 5개), 정답표와의 일치, 지문·보기 연결 개수.
3. **독립 모델 대조**: 문항 크롭과 정규화문을 별도 모델(이 사이트의 JEV 등)에 보여 주고 불일치만 사람에게 올린다. 같은 모델이 만들고 같은 모델이 검증하지 않는다.
4. **표본 검수로 품질 보증**: 승격 전에 무작위 200문항을 뽑아 독립 검수하고 오류율과 신뢰구간을 기록한다. 이 수치를 `verified` 승격의 근거로 삼는다.
5. 이슈 코드(`LINE_JOIN_AMBIGUOUS` 등)별 건수와 해소율을 대시보드로 남겨, 어떤 규칙이 약한지 드러낸다.

### 4.5 작업물 관리

- **커밋**: `data/question-bank/`(README, schema.sql, gold, 교정 JSON), 규칙 문서, 적용 스크립트, 검증 스크립트를 git 에 올릴 것. 지금은 디스크 장애·실수로 잃을 수 있는 상태다. 큰 산출물(SQLite, 크롭 이미지)은 커밋하지 않고 재생성 절차와 해시만 남긴다.
- **중간 DB 정리**: v1~v35 등 103개 중간 DB 는 재현 가능한 산출물이다. 승격 시점의 것만 남기고 삭제한다(`work/` 27GB).
- **고정된 기준선**: 어느 DB 가 "현재 기준"인지 `data/question-bank/README.md` 에 파일명·SHA-256·생성 스크립트·입력 해시로 명시한다.

### 4.5-b 범위와 우선순위

문항 DB 는 전체 시험의 6%만 덮는다. 전부 하려 하지 말고 수요 기준으로 좁혀 쓰임새를 먼저 검증할 것. 예: 최근 3년 수능·평가원 모평의 국어·수학(선택과목 포함) → 결과로 4.1의 소비처를 검증 → 확장.

## 6. 요청

- 위 4.2의 유형별 기준을 그대로 받을지, 다른 기준이 있다면 근거와 함께 알려 달라.
- 현재 `candidate_unverified` 16,288건 중 **어떤 규칙으로 후보를 만들었고, 그 규칙의 오류율을 아직 측정하지 않았다면** 표본 검수 계획을 세워 달라.
- 문항 본문을 사이트에 공개할 계획이 있다면 미리 알려 달라. 저작권·애드센스 검토가 필요하다.
